# campus-classroom

校园空教室查询工具：一个**可点击的单文件原型** + 我在做它时的设计取舍。

起因是自己的真实困扰：晚上找自习室，得打开教务系统一格格对课表，走到教室发现有人上课，再换一间。信息其实是有的，只是没被加工成"这间教室现在空不空"。这个仓库就是我把它做成一个能点、能演示的原型的过程记录。

> 说明：这是**个人练习项目**，不是课程作业，也没有真实用户调研数据与线上运营。原型里的教室数据全部是手工模拟的，用来验证交互流程，不代表任何真实课程安排。

## 直接看原型

**在线版（GitHub Pages）**：<https://xingjiang7777.github.io/campus-classroom/> — 手机浏览器也能打开。

本地版：打开 [`prototype/index.html`](prototype/index.html) 即可（单文件，无依赖、无构建、断网可跑）。

可交互的点：

- 切换时段（现在 / 今晚 / 明早）→ 列表与"可用至"同步变化
- 筛选（有插座 / 20 人以上 / 只看 A 楼）→ 无结果时有空状态与"清除筛选"
- 点教室卡片 → 底部弹层看容量、插座、今日后续占用
- 某些时段会触发"教学楼都满了"的兜底文案，而不是一片空白

## 这个原型想验证的三件事

做它不是为了好看，是想验证三个设计判断站不站得住：

| 判断 | 在原型里怎么体现 |
| --- | --- |
| 用户要的是"能待到几点"，不只是"现在空" | 列表主字段是「可用至 21:40」，不是「空闲」两个字 |
| 查到"不准"比"查不到"更糟 | 每张卡片标注数据更新时间；宁可显示"数据存疑"也不显示一个错的空闲 |
| 交互必须极短，否则不如直接去碰运气 | 砍掉登录、引导页、首页推荐，打开即列表，筛选全在一行 |

## 明确不做的

图书馆座位预约、社交组队、教室借用申请、多校覆盖。这几个都是"看起来相关、实际会把这个小工具拖死"的需求，第一版一律不碰。

## 关键取舍

**为什么不做众包上报？**
没有激励的众包会退化成"少数人维护、多数人受益"，数据反而更烂。所以纠错只做"存疑标记"，不试图替代课表数据。

**为什么把"可用至几点"当核心字段？**
只知道"现在空"不够——坐十分钟被赶出来，体验比没查到还差。这一条是相对教务系统的直接改进点。

**为什么排序是"距离 → 空置时长 → 插座"？**
场景发生在"路上"，用户已经出门了，先要近的；其次是能待多久；插座是加分项不是决定项。
