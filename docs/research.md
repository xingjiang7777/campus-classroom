# 需求调研记录：校园空教室查询

> 调研时间：2026 年 3 月，为期两周。样本全部来自本校（一所普通本科院校），不代表所有学校。
> 这份文档保留的是**原始结论和推导过程**，包括被推翻的假设——面试时最容易被追问的就是"你一开始想错了什么"。

## 1. 调研目标

先明确要验证什么，避免"问了一圈只得到'挺好的'"。

| 假设 | 验证方式 | 结论 |
| --- | --- | --- |
| H1：学生找不到空教室，是因为没有查询工具 | 问卷 + 访谈 | **部分成立**：工具不是没有，是"难用/不准" |
| H2：主要需求是"现在有没有空教室" | 问卷 | **不成立**：68% 的查询是"今晚/明早"的**未来时段** |
| H3：大家愿意为了准确信息多花操作成本 | 访谈 | **不成立**：超过 3 步就流失 |
| H4：插座、空调是次要因素 | 问卷排序 | **不成立**：插座排在"距离"之后第二位 |

H2 和 H4 是被数据推翻的两个假设，直接改变了产品形态（见第 5 节）。

## 2. 方法与样本

| 方式 | 数量 | 说明 |
| --- | --- | --- |
| 线上问卷 | 126 份有效 | 通过班级群与两个自习社群发放，剔除答题时长 < 40 s 的 11 份 |
| 半结构化访谈 | 12 人 | 大一 4、大二 4、大三 3、大四 1；含 3 位经常去图书馆的"非目标用户" |
| 竞品体验 | 3 款 | 逐个走完"查今晚 7 点空教室"的完整任务 |
| 实地观察 | 3 次 | 晚 6:30–7:30 在教学楼记录实际空置与系统显示是否一致 |

样本偏差要主动承认：**问卷通过自习社群发放，天然偏向"已经在自习的人"**，所以"需求强度"这一项可能被高估。访谈里特意补了 3 位不去自习的同学来平衡。

## 3. 问卷关键数据

**Q1 你多久需要查一次空教室？**

| 频次 | 占比 |
| --- | --- |
| 每周 3 次以上 | 41% |
| 每周 1–2 次 | 34% |
| 每月几次 | 18% |
| 几乎不 | 7% |

→ 75% 的人每周至少查一次，属于**高频刚需**，不是伪需求。

**Q2 你现在怎么查？**（多选）

| 方式 | 占比 |
| --- | --- |
| 教务系统课表页自己推 | 62% |
| 问同学 / 群里问 | 47% |
| 直接去教学楼碰运气 | 39% |
| 学校小程序 / 公众号 | 21% |
| 第三方 App（超级课程表等） | 14% |

→ 62% 靠"自己推课表"，说明**信息是有的，只是没有被加工成答案**。这是本项目最核心的切入点。

**Q3 查的时候最关心什么？**（排序题，取前三位加权）

| 因素 | 加权得分 |
| --- | --- |
| 有没有空位（准确） | 4.6 |
| 离我多远 | 4.1 |
| 有没有插座 | 3.7 |
| 空调 / 暖气 | 3.2 |
| 能不能待到几点 | 3.0 |
| 人多不多 | 2.4 |

→ 插座排第三，是原假设 H4 被推翻的地方。访谈里的原话："没插座的话，两小时就没电了，等于白来。"

**Q4 你能接受几次操作？**

| 可接受步骤 | 占比 |
| --- | --- |
| 1–2 步 | 58% |
| 3 步 | 33% |
| 4 步以上 | 9% |

→ 91% 要求 3 步内拿到答案，直接约束了交互设计（见 PRD 的"3 步原则"）。

## 4. 访谈要点

12 人访谈，每人 20–30 分钟，围绕"最近一次找教室"的具体经历展开，不问"你想要什么功能"。

**发现 1：真正的问题不是"查不到"，而是"查到了不准"。**
> "教务系统显示 A305 没课，我走过去发现在上选修课，因为临时调课没更新。"（大二，男）

这是最关键的发现：**数据时效性 > 功能丰富度**。如果数据不准，功能做得再多也是负分。

**发现 2：决策发生在"路上"，不在"宿舍"。**
> "一般是从食堂出来才想起来，边走边看手机。"（大三，女）

→ 移动端优先，首屏必须直接给结果，不能有引导页、不能要登录。

**发现 3：结伴自习是常态，分享是隐式需求。**
> "我会截图发群里问有没有人一起。"（大二，女）

→ 提供"生成一张可分享的卡片"，比自己做一个社交功能更轻、更符合现有习惯。

**发现 4：非目标用户的反馈同样有价值。**
3 位常去图书馆的同学明确说"不需要"，理由是"图书馆位置固定，不用查"。→ 说明产品边界应该限定在**教学楼**，不要试图覆盖图书馆座位预约（那是另一个问题）。

## 5. 结论与对产品的影响

从调研到设计，四条结论直接落到了 PRD 里：

| 调研结论 | 产品决策 |
| --- | --- |
| 62% 靠自己推课表 → 信息存在但未加工 | 核心功能是"把课表数据算成空教室"，不是新建数据源 |
| 数据不准比没有更糟 | 增加"数据更新时间"与"手动纠错"入口，把不确定性显式告诉用户 |
| 68% 查未来时段 | 首屏默认"现在"，但时间选择器放在第一屏，一次点击切到"今晚/明早" |
| 91% 要求 3 步内 | 砍掉登录、砍掉引导页、砍掉首页推荐，打开即结果 |

## 6. 没做的事（以及为什么）

- **没做用户画像细分**：样本 126 份，细分到"大一/大二/大三"每层只有 30 份左右，结论不显著，强行分群是自欺欺人；
- **没做定量可用性测试**：只做了 5 人走查（见 PRD 附录），样本太小，只能发现明显问题，不能证明"更好用"；
- **没验证商业化**：这是校园工具，不在本次范围内，但 PRD 的"开放问题"里留了记录。

## 7. 复盘

做得好的：先写假设再调研，所以能明确说出"哪两个假设被推翻了"，而不是拿着一堆数据说"用户需要"。

做得不好的：问卷在自习社群发放，样本偏"高频用户"，导致对整体需求的强度估计偏高。如果重做，会在食堂和宿舍楼门口做随机拦截，样本更接近真实分布。
